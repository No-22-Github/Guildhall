# 可靠性修订（2026-09-05）

本文件记录相对最初 demo 规格的明确调整。保留像素公会前端的后续设计空间，本轮只改链路和必要操作。

- 生成、编辑保存、张贴、派单使用统一委托校验：目标/约束/现状调研/范围非空，验收连续编号且有负向条目，范围为仓库相对 glob。这里只校验可机械判定的结构，不宣称能证明任意自然语言命令有效。`*` 不跨目录，`**` 跨目录。
- 委托书张贴后冻结；后续生成和编辑入口拒绝修改。外部手改会在交付快照比对时被发现。
- 验收 JSON 强类型且非空；检查序号、步骤原文与委托逐条匹配，summary/evidence 必填。解析失败仍不自动重试。原始输出完整保存在 error。
- 鉴定人首条输入显式带相对创建基点的 diff，不读取冒险者报告。新增的范围内非忽略文件在冒险者结束后加入 index，使新增文件进入 diff、完整性检查和交付；项目应通过 .gitignore 排除构建产物。
- 服务端对 Git 路径清单做范围检查。Tests/ 等大小写测试目录也识别。touched_tests 是显著风险提示，独立于 pass/fail；不再仅因新增测试判 disputed。
- 保留 diff HEAD 摘要，同时比对 HEAD、index tree、tracked 文件原始内容和模式，防止提交和二进制变更绕过。忽略的构建缓存不交付。
- 每张单只有一个阶段任务。活任务存在时恢复请求返回 409；不把“推进”当作强制打断。appraised/disputed 可以显式重验，记录 recovery 历史并废弃旧结论快照；普通 transition 仍执行封闭转移表。
- SSE 的 Last-Event-ID 优先于初始 query，从下一条续读；先订阅再重放避免缺口；事件行数按文件大小验证后缓存，避免每条扫描全文件。
- 接受改为“接受并合并”：预览目标分支，用户确认后生成独立交付提交，目标仓库只允许干净工作区和基点未前进时快进。不改冒险者 worktree/index。记录 delivery_commit，合并后中断可重试。不自动解冲突、不推送。
- 历史验收缺少快照时禁止直接合并，需先重验。已 settled 历史不会补合并。验收后的新改动必须重新验收。非忽略范围内未跟踪文件阻止交付，需纳入 Git 后重验。
- 前台只在有证据时提出异议，取消“至少争论一次”的强制要求。

验证分层：pytest 使用隔离仓库与 fake ACP，Git 交付实际执行；浏览器检查使用独立端口的临时项目；没有消耗真实模型的端到端运行。
