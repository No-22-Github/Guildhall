# 可靠性修订（2026-09-05）

本文件记录相对最初 demo 规格的明确调整。保留像素公会前端的后续设计空间，本轮只改链路和必要操作。

- 生成、编辑保存、张贴、派单使用统一委托校验：目标/约束/现状调研/范围非空，验收连续编号且有负向条目，范围为仓库相对 glob。这里只校验可机械判定的结构，不宣称能证明任意自然语言命令有效。`*` 不跨目录，`**` 跨目录。
- 委托书张贴后冻结；后续生成和编辑入口拒绝修改。外部手改会在交付快照比对时被发现。
- 验收 JSON 强类型且非空；检查序号、步骤原文与委托逐条匹配，summary/evidence 必填。解析失败仍不自动重试。原始输出完整保存在 error。
- 鉴定人首条输入显式带相对创建基点的 diff，不读取冒险者报告。新增的范围内非忽略文件在冒险者结束后加入 index，使新增文件进入 diff、完整性检查和交付；项目应通过 .gitignore 排除构建产物。
- 服务端对 Git 路径清单做范围检查。Tests/ 等大小写测试目录也识别。touched_tests 是显著风险提示，独立于 pass/fail；不再仅因新增测试判 disputed。
- 保留 diff HEAD 摘要，同时比对 HEAD、index tree、tracked 文件原始内容和模式，防止提交和二进制变更绕过。忽略的构建缓存不交付。
- 每张单只有一个阶段任务。活任务存在时恢复请求返回 409；不把“推进”当作强制打断。appraised/disputed 可以显式重验，记录 recovery 历史并废弃旧结论快照；普通 transition 仍执行封闭转移表。
- SSE 的 Last-Event-ID 优先于初始 query，从下一条续读；先订阅再重放避免缺口；事件行数按文件大小验证后缓存，避免每条扫描全文件。
- 接受改为“接受并合并”：预览目标分支，用户确认后生成独立交付提交，目标仓库只允许已跟踪文件和暂存区干净、基点未前进时快进；无覆盖风险的未跟踪文件允许保留。不改冒险者 worktree/index。记录 delivery_commit，合并后中断可重试。不自动解冲突、不推送。
- 历史验收缺少快照时禁止直接合并，需先重验。已 settled 历史不会补合并。验收后的新改动必须重新验收。非忽略范围内未跟踪文件阻止交付，需纳入 Git 后重验。
- 前台只在有证据时提出异议，取消“至少争论一次”的强制要求。

## 需求单交付方式（2026-09-06）

真实模型在问完问题后，倾向于把整份需求单直接吐进对话；旧链路靠“生成需求单”短语/按钮开
generation turn 才能截获文本，识别面过窄，导致 quest.md 不落盘、张贴面板不出现。

- receptionist 的交付契约改为**写文件**：prompt 注入 quest.md 的绝对路径，问完后用写文件工具直接写盘；对话里不输出全文（系统会自动回显到界面需求单面板），用户要求修改时先重新读文件再改。
- 服务端在每个 receptionist chat turn 结束后 reconcile：以服务端为准修正 frontmatter 事实字段（id/project/created，title 保留 Agent 的），跑张贴闸门；通过则落盘规范化版本并发 `_guildhall/quest_md_updated`，失败发 `_guildhall/quest_md_rejected` 并把原因作为系统消息自动回喂（连续上限 2 次，防拉扯），张贴闸门仍是最终兜底。
- 「生成需求单」按钮与短语触发的 generation turn 保留为兜底：Agent 在 turn 里写了文件则以文件为准；没写文件仍按旧的文本截获路径收口（旧会话/旧模型兼容）。
- 用户手动编辑（PUT /quest）不触发 reconcile：本轮 turn 内文件没变化即无事发生，手改的校验仍发生在张贴时。

验证分层：pytest 使用隔离仓库与 fake ACP，Git 交付实际执行；浏览器检查使用独立端口的临时项目；没有消耗真实模型的端到端运行。

## Git 交付保护（2026-09-07）

- 未跟踪文件不再一律阻止交付；包括已忽略文件在内，若与交付路径同名或有文件/目录前缀冲突则阻止，并返回具体路径。按仓库 core.ignorecase 处理大小写。
- 已跟踪文件的工作区和暂存区分别检查，避免两者改动相互抵消；保留目标分支、基点和验收快照检查；未结束的 merge/rebase/cherry-pick/revert 操作阻止交付。
- 同一 Git common directory 的 Guildhall 交付通过文件锁串行化，并发请求立即返回稍后重试；生成提交后、合并前重新预检，merge 使用 --ff-only --no-overwrite-ignore。该锁不阻止外部编辑器和 Git 命令，不提供全局文件系统事务保证。
- 合并后检查 HEAD 与已跟踪状态，无关未跟踪文件不再造成成功后误报。测试实际核对普通及已忽略数据保留，并覆盖交付重试。
- Review 提供“重新检查”，窗口重新获得焦点和交付请求结束后也刷新；请求期间禁用合并，丢弃旧任务/旧请求返回值，展示阻塞路径。
